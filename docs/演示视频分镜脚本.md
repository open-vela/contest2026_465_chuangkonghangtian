## 0. 一句话原则

**AI Coding 录屏是"佐证"，不是"主体"。** 它证明"这个作品是 AI-Native 做出来的"，
所以剪成 **20~25 秒、加速 6~8 倍、配数字字幕**，插在 **中后段（3:05 左右）**，
**不要整段堆在片尾**——片尾 30 秒是"展示效果"评分的最后印象，不能交给慢节奏聊天记录。

总长控制在 **4:45~4:55**，留 5 秒余量，超 5:00 直接不合规。

## 3. AI Coding 录屏：怎么录、怎么剪

### 3.1 录什么（不要录整段流水账）

只录 **3 个"结论时刻"**，每个 40~60 秒原始时长，剪完各 6~8 秒：

| 片段 | 内容 | 为什么好看 |
|---|---|---|
| A | 提问定位按键问题 → AI 给出"引脚从未配置"的结论 | 有反转、有推理 |
| B | AI 贴出 SD 写卡让位接收窗口的修改 diff | 有具体技术取舍 |
| C | 稳定性测试结果输出（异常字节 0） | 有量化结果 |

**没有现成录屏也没关系**：可以在 DSH 里把这三个问题**重新问一遍**（用本仓库真实代码），
当场录屏即可，内容与真实开发过程一致。

### 3.2 怎么录

- 工具：OBS Studio 或 剪映「录屏」功能，**1920×1080 / 30 或 60fps**
- 关掉无关窗口、通知；浏览器/编辑器**放大字号**（评委在手机上看要能看清）
- 录之前先跑一遍，保证关键结论出现在屏幕中心
- 同时把终端输出**复制成文本**，后面做字幕更清楚

### 3.3 在剪映里怎么处理（25 秒）

1. 三段素材按 A→B→C 顺序排，**每段先裁到只留结论那一屏**
2. 选中片段 → 「变速」→「常规变速」→ **6~8 倍**（对话类 8 倍，代码类 4~6 倍）
3. 关键结论处 **分割并定格 1 秒**，加「强调」音效
4. 用文本框把第 5 节那四条数字字幕逐条弹出（2 秒/条）
5. 整段加一个细边框 + 标题条「AI-Native 开发过程」，与实拍素材区分开
6. 旁白按第 5 节台词录，**语速放正常**（画面快、声音稳，观感最好）

> ⚠️ 千万别出现的做法：把几十分钟对话按原速丢在片尾。信息密度低 + 字小 + 无解说，
> 观众只会觉得"没剪完"。

## 4. 剪映操作清单（按顺序做）

1. **新建草稿** → 导入全部素材（`evidence/videos/*.mp4`、补拍视频、截图）
2. **排骨架**：按第 1 节七段顺序粗剪，**先不管特效**，总长压到 4:45
3. **写台词**：把第 2 节旁白抄进「文本」，用「朗读」生成配音（或自己录）
4. **对轴**：旁白贴画面，画面不够就补空镜（实物特写/日志截图）
5. **识别字幕**：右键音频 →「识别字幕」→ 统一字体（推荐思源黑体 Bold）、字号 8~10、底部居中
6. **AI 段变速 + 数字字幕**（第 3.3 节）
7. **混音**：旁白 -3dB，背景音乐 -18~-22dB，音乐**绝不压过人声**；关键音效（点火声、蜂鸣器）保留同期声
8. **统一调色**：实拍片段稍微提亮，让屏幕与硬件都看得清
9. **导出**：1080p / 30fps / H.264 / 码率 8~12 Mbps / mp4，文件名 `队伍名-作品名-演示视频.mp4`

## 5.5 现有素材专属精简表（手机拍 4 分钟：屏幕 + 板子，有现场声）

**定位：这段 4 分钟录像 = 全片脊柱，最终只留约 100 秒，其余靠插入镜头补齐。**

### 5.5.1 先做减法：从 4 分钟砍到约 100 秒

对着原片按下面这张表逐段处理（时间点按实际内容对，不必卡死秒数）：

| 原片内容 | 原始时长 | 处理 | 留用 |
|---|---|---|---|
| 开机等待 / 屏幕未亮 | ~20s | **整段删掉**（或 8 倍速留 2s 做"启动感"） | 2s |
| 待机画面 + 无操作停顿 | ~30s | 只留 5s 原速，其余删 | 5s |
| 按 KEY2 确认（蜂鸣器） | ~20s | **原速保留**（这是交互操作证据） | 12s |
| 按 KEY1 点火 + 音效 | ~20s | **原速保留，最重要的一下** | 15s |
| 飞行阶段 + 反复翻页 | ~90s | 重复翻页删掉，只留 2 页各 8s，其余 4 倍速 | 25s |
| 结束 / 回收阶段 | ~30s | 留 8s，其余 2 倍速 | 8s |
| 拔卡 → 读卡器 → 打开 CSV | ~30s | 2 倍速（观感够快） | 15s |
| 手部按键特写（若拍到） | — | 原速保留 | 10s |
| 总计 | 240s | — | **≈92s** |

> 口诀：**只删不加**。同一块屏幕重复看第三遍对评委没有新增信息，宁可插一个实物镜头。

### 5.5.2 手机素材的修复参数（剪映）

| 问题 | 剪映操作 |
|---|---|
| 手抖 | 选中片段 →「画面」→「防抖」→ **最稳定** |
| 屏幕在画面里太小 | 「裁剪」→ 16:9，把屏幕区域放大铺满；竖拍则用「比例 9:16」或加模糊背景补边 |
| 反光 / 摩尔纹 | 「调节」→ 高光 −15、对比度 +5、锐化 +10 |
| 现场噪声大 | 「音频」→「降噪」开；旁白 −3dB、**现场声 −12dB、背景音乐 −20dB** |
| 点火音效要突出 | 把现场声**局部拉回 0dB** 2~3 秒，其余时间压低 |
| 屏幕白平衡偏黄 | 「调节」→ 色温 −5、饱和度 +5 |

### 5.6.2 1 分钟"第一视角操作"的处理步骤（剪映）

1. **先看一遍，用时间轴标记 3 个信息点**：① AI 说出问题根因的一句 ② 代码 diff 出现的一屏 ③ 测试结果输出
2. **非信息段**：选中 →「变速」→ 常规变速 **6~8 倍**（打字、加载、等待全部快放）
3. **信息点**：保持 **原速**，并「定格」1 秒 + 加"叮"提示音，让观众看清
4. **加标题条**：左上角常驻「AI-Native 开发过程 · 实际录屏」
5. **声音**：这类录屏一般只有键盘声/静音 → **整段静音**，用旁白 + 轻音乐铺底
6. **旁白必须点题**：不能指望评委自己看懂，例如
   > "这段是真实的开发录屏：我们问 AI'按键为什么没反应'，它直接定位到按键引脚在板级配置里从未被使能。"
7. **数字字幕**（第 5 节那四条：95% / 7479 行 / 9125 万 tokens / MiMo 2008 次）逐条弹出，2 秒一条
